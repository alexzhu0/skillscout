# Local evidence selection design

状态：离线实现、完整测试及最终审查完成；仍未执行真实 v3 提取，尚未证明生成的 Skill 有用。
基线：`723ad512938cd376481492f6727a46fb3b824aca`，现有 PR #40。
范围：本地单 README 提取；不扩大到生产发现、发布或 Phase 6 campaign。

## 产品目标与这次修复的关系

SkillScout 要把公开 GitHub 仓库中的可复用 AI 工作流，转化为有用、
可追溯、经过安全检查与独立 Reviewer 检查的 Agent Skill Draft PR。
人类负责审核与合并；系统不执行来源代码，不自动合并。

近期的产品目标是先产出一个值得使用的 Skill，再比较任务单独运行、
提供原始 README、提供 Skill 三种条件下的效果。审批记录和离线测试
本身不是产品价值，也不等于这个目标已经达成。

本次只解决其中的机械性证据构造问题，不声称解决所有语义质量问题。

## 已知失败事实

真实 run `d3aaeaddcc944809b148fa7b72f87246` 的 DeepSeek Flash 请求成功，
返回了结构合法的两个工作流。随后确定性校验将二者拒绝：

- 工作流 0：至少一段引用不是对应输入的完全一致子串。
- 工作流 1：三个原文引用字段命中 URL 禁令，未报告非原文引用错误。

被拒原文未留存，不能推断具体文字差异、链接地址或恶意行为。
这是 `all_workflows_dropped`，不是模型判断仓库没有工作流。
当前提取预算已达 3/3；这份设计不授权新模型请求或重试旧 run。

## 方案选择

推荐：**受限证据目录 + 模型选编号 + 程序回填原文**。

- 精确复制、文件路径、blob SHA 和内容哈希交给确定性程序。
- 模型只负责工作流含义、步骤和哪些证据支持哪些主张。
- 引用候选提前通过原有安全规则；输出指令仍须独立通过原有规则。

另两个方案是继续要求模型抄写原文，以及允许 URL 进入证据字段。
前者仍保留已观察到的复制失败模式；后者需要重新评估证据进入生成器、
Reviewer 与最终包的边界，影响范围更大。本轮均不采用。

本方案不会让所有 README 都变得可提取：如果关键说明只存在于被排除的
片段中，应记录证据不足，而不是伪造、改写或拼接一份“安全原文”。

## 输入与证据目录

1. 继续使用已验证的固定提交、许可证、单 README 路径和读取限额。
2. 新增纯函数，从已读取的文本按原顺序构造目录；不请求网络或模型。
3. 排除 Markdown 围栏代码块、空行，以及命中任何现有 forbidden-text
   规则的完整原始行。必须在切片前检查整行，不能切断 URL、密钥模式或
   命令模式来绕过检查。围栏必须保守匹配；未闭合围栏到文件末尾均排除。
4. 其余行按原始字符偏移切成最长 280 字符的连续片段；不得规范化空格、
   改写 Markdown、删除字符后拼接、翻译或补全。每个片段再次检查安全规则。
5. 最多 128 个片段，保持原文顺序；超过上限只取前 128 个并记录截断事实。
   每项绑定程序生成的编号（`e0001` 起，目录内唯一）、路径、blob SHA、
   内容哈希、原始起止字符偏移（左闭右开）和原文。编号只在本次目录内解析。
6. 模型只接收这些带编号的片段及必要的结构化来源元数据，不再重复发送
   完整 README。它必须知道输入可能不完整，缺乏支持时应返回零工作流。
7. 完整语义输入（固定提示词、用户载荷及响应 schema）按 UTF-8 字节计量，
   上限 65,536 bytes；超过则在请求前停止，不静默裁剪提示词或 schema。
   不提高现有组织级读取或输出 token 上限。
8. 目录为空时不调用模型；使用独立、固定的 `no_eligible_evidence` 诊断，
   不将其描述为模型作出的 `no_workflow` 判断。

片段内容始终是低优先级的不可信数据。拥有编号不代表内容可信、可以执行，
也不证明它在语义上支持某个主张。不得将片段插入受信任提示词。

## 模型响应与回填

新增仅供本地新版提取使用的严格响应类型。保留现有工作流语义字段及其
数量、长度上限；每个 evidence 只允许 `evidence_id` 和 `supports`。
模型不得再提供 excerpt、path、blob SHA 或 content hash；额外字段拒绝。

程序只在本次调用的目录内解析编号，补齐既有 `EvidenceRef` 所需内容。
未知编号拒绝对应工作流；禁止模糊匹配、查找其他文件或让模型补救。
工作流及每个步骤都必须有证据。步骤引用必须出现在该工作流顶层的证据
集合中；不自动增加模型没有声明的顶层证据来掩盖不一致。

回填后继续运行现有 `validate_workflow_boundaries`。模型写出的步骤、
支持说明等文字仍可能触发拒绝；编号方案不豁免任何输出安全检查。
通过后生成原有 `WorkflowSpec`，保留原有许可证和来源绑定。

这将“选择证据的语义判断”和“复制证据的机械工作”分开，但不证明引用
足以支持主张。后续 qualification、独立 Reviewer 和人工审核保持必要。

## 版本、状态与下游边界

- 新身份固定为 `local-readme-v3` scope、`evidence-catalog-v1` 目录策略、
  `extract-local-evidence-select-v1` 提示词、`extractor-evidence-selection-v1`
  响应 schema，以及 `retry-local-readme-v3-once` 单次尝试策略。
  旧 v1/v2 解析与历史事实保持不变。
- 不修改原有 `WorkflowSpec`、生成器或 Reviewer 的输入契约；新版响应
  在提取阶段内部完成回填后才交给它们。
- 导出与 build 继续仅在显式本地模式接受该来源。版本、策略、来源 scope
  和一次尝试限制必须由状态桥重新核验；默认 hosted/publication 仍拒绝。
- 目录在内存中构造；摘要由规范 JSON 的 scope、目录策略和有序目录项整体
  计算 SHA-256；记录策略、摘要、片段数、截断状态与固定诊断。
  目录摘要用于审计，不单独赋予发布或证据真实性权限。持久 WorkflowSpec
  保留已通过校验的选中引用，不另存全部目录或拒绝的模型原文。继承 v2
  的内容无关诊断上限及 summary/refusal 自由文本不持久化规则。
- 单次调用最多一次模型请求，SDK retry 为零，无 correction。未知结果
  不重放；已完成失败也不能通过改目录、清库或换状态目录来隐式重试。
- 不新增数据库表、远端状态图、GitHub workflow、审批入口或自动化身份。

## 验证与完成标准

先写失败测试，再实现；全部使用本地 fixture 和替代 transport，无模型费用。

1. 带 Markdown、Unicode、CRLF、长行和重复文本的输入：回填值始终是同一
   原文的精确子串，偏移与哈希匹配；无空白规范化或重写。
2. 含 URL 的行不成为引用候选；临近的正常说明仍可引用。不访问 URL。
   全部候选不合格时请求计数为零；不能为生成结果而放宽校验。
3. 秘密模式、命令模式、围栏代码块和未闭合围栏被排除；切片不能洗白模式。
4. 目录项数和完整输入字节上限生效，超限在模型请求前停止。
5. 模型只选编号即可得到有效、来源绑定的 WorkflowSpec。额外字段、未知
   编号、缺失步骤证据及步骤/顶层证据不一致均失败关闭。
6. 不可信片段中的伪系统指令不进入受信任消息，也不能触发工具或执行。
   诊断不保存被拒文本、秘密值或模型自由文本。
7. 新版实际生产组合的离线测试贯穿提取、导出和本地 build；原有官方格式
   校验与独立 Reviewer 的替代 transport 仍生效；发布来源检查必须拒绝。
8. v1/v2 历史读取、默认/hosted 行为、未知结果恢复、单次调用和不重复调用
   均有回归测试；代码审查与适用的完整离线套件通过。

完成后交付：代码、测试结果、更新后的 README/AGENTS/RELEASE，以及同一个
PR #40 的准确状态。不把离线通过称为真实提取成功。

新的真实 Flash 试验需要另行明确预算；旧试验保持终止。新试验若成功，
再用最多一个候选进入生成、检查、独立审核和用途对比，继续朝“一个有用的
Skill”推进，不重新启动五仓库发现或发布 campaign。
