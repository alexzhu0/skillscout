## Trust Boundaries

| Boundary | Description |
|---|---|
| WorkflowSpec → Generator request | Structured but model-derived evidence crosses into a fresh external LLM request as inert user data. |
| Generator output → trusted renderer | Model semantic fields remain untrusted and must not gain path, mode, identity, or tool authority. |
| Rendered package → local filesystem | Exact approved bytes are materialized under link/ownership/mode/durability controls. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-GEN | Tampering / Elevation of Privilege | model draft and renderer | high | mitigate | Closed semantic schema, trusted path/frontmatter/mode/identity renderer, fixed tree, no tools/scripts/binaries, and adversarial tests. |
| T-03-LINEAGE | Spoofing | slug/lineage mapping | high | mitigate | Full versioned lineage identity authorizes updates; short suffix is presentation only; collisions and ambiguity fail closed. |
| T-03-03-FS | Tampering | package materialization | high | mitigate | Anchored no-follow descriptor writes, identity checks, retained lock, exact modes, atomic replace and fatal fsync. |
| T-03-03-ID | Information Disclosure | credentials/source/model output | high | mitigate | Header-only key, WorkflowSpec-only payload, bounded provenance, registered excerpts, sanitized outcomes and canary sweeps. |
| T-03-03-DOS | Denial of Service | model/package sizes | medium | mitigate | Pydantic caps, output-token cap, file/count/line/token/package limits, and preflight before filesystem creation. |
</threat_model>
